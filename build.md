# Build cardBot from scratch

Use this whole file as the build prompt in a **new, empty workspace**. The reference is `scratch` at [3c7a6b9](https://github.com/wdphoto/cardBot/tree/3c7a6b95230fd4996817b423f86e0944917a4852), version `0.10.0-dev`; you do not need the old checkout. Implement and test the application, not another plan. Do not reset the existing repo, install anything into the user's login session, touch real cards, push, tag, or publish a release.

## The job

Build `cardbot`, a single Go executable for a photographer at a card reader. Inserting a camera card should answer three questions: **What's on it? What did I last ingest? What will this selection copy, and where?** The photographer chooses whether to copy, skip, or eject. Insertion alone never copies anything. Never delete, rename, tag, or format source media.

Use module `github.com/wdphoto/cardBot` (case matters), Go 1.26.8 or newer, Cobra for the CLI, Viper for explicit overrides. macOS is primary; Linux is best effort; Windows must compile with unsupported-operation stubs, not pretend to work. Keep the CLI, existing file formats, destination layout, and safety rules below. Package names, number of files, banner art, and spinner timings are not compatibility requirements.

## Start with this acceptance case

Make a temporary `CARD/DCIM/100NIKON/` with three tiny files; `DEST` is a sibling directory that doesn't exist yet. Give `CLIP.MOV` a local mtime of 2026-03-14 14:30:51 and `DSC_0001.NEF` 14:30:52 that day. No valid EXIF is needed. Give `DSC_0001.XMP` a next-day mtime and an XMP rating attribute `xmp:Rating="4"`.

The photographer's preview command is `CARDBOT_NAMING=timestamp cardbot --dry-run --dest "$DEST" "$CARD"`, then `s` and Enter. Exercise this flow with a fake detector in tests.

- The scan reports **one photo, one video, one starred**, not three media files. In `timestamp` mode, previewing selects (`s`) maps the NEF and XMP to `DEST/2026-03-14/100NIKON/260314T143052_0002.NEF` and `.XMP`. The earlier, unselected video owns `0001`. Preview creates neither `DEST` nor `CARD/.cardbot`.
- A real `s` with `full` verification publishes those two files and records `selects`. An ensuing `a` adds only `260314T143051_0001.MOV` and skips the identical pair. With `original` naming the NEF would instead land at `DEST/2026-03-14/100NIKON/DSC_0001.NEF`.
- In a fresh session, change one destination byte without changing the length. `full` must report a conflict and leave the destination alone; `size` may skip it but must not claim the bytes match. This distinction matters more than the progress animation.

## Foreground workflow

- `cardbot` watches for mounts containing a `DCIM` directory, including cards already present. `cardbot [flags] CARD_ROOT` analyzes that path immediately while still receiving detector events. Retry a briefly missing `DCIM` on a targeted mount; if invalid, explain why and disable copy. Preserve significant path whitespace, including trailing spaces on volume names, through argument parsing, setup, planning, and launching.
- Poll `/Volumes` about once per second in normal macOS builds, even with cgo available. Keep native DiskArbitration opt-in (`darwin`, cgo, `cardbot_native`). On Linux poll flat and user-nested mounts under `/run/media`, `/media`, `/mnt`. Detect insertions/removals once, queue additional cards FIFO, and drop removed cards from the queue. Show path, used/total storage, inferred camera brand, and available hardware details (device ID, filesystem, read-only flag, reader/card model). Treat an unavailable field as unknown; never test writability by writing to a card.
- Walk `DCIM` recursively, skipping dotfiles, hidden directories, and symlinks. The **overview** counts recognized media, case-insensitively: photos `NEF NRW CR2 CR3 CRW ARW SRF SR2 RAF ORF RW2 DNG PEF 3FR IIQ JPG JPEG TIF TIFF HEIC HEIF PNG`; videos `MOV MP4 AVI MXF MTS M2TS R3D BRAW`. **Copy All** takes all visible regular files under `DCIM`, even unknown types and orphan sidecars. It does not copy the whole volume.
- Use bounded, cancellable metadata reads (a Go EXIF decoder such as `imagemeta`, not a required external tool). Prefer EXIF `DateTimeOriginal`, fall back to file mtime. Prefer a positive EXIF rating, then embedded XMP, then same-stem external XMP; recognize 1–5 stars in element or attribute form. Missing metadata does not disqualify a photo. Show deduplicated bodies/lenses, starred count, newest date groups first with sizes/counts/extensions, photo/video totals, history, destination, and naming mode.
- Use **line input + Enter**, not raw key mode. `a` all; `s` starred selects; `p` photos; `v` videos; `t` / `y` photos from today / yesterday by local calendar date; `i` hardware info; `?` help; `\` cancel copy; `e` explicitly eject/unmount; `x` finish this card without ejecting. Ctrl+C shuts down. Say when nothing matches, scanning isn't finished, or a mode already completed this session. Successful `all` covers the other modes; a preview never marks one complete.
- Keep one owner of session state: waiting → analyzing → ready → copying → ready/next card, or shutdown. Run I/O off the input loop. Register cancellation **before** starting work. Block another copy, `e`, and `x` while copying. Removal or shutdown cancels work; wait for the worker before advancing. Tie completions to a session ID, not just a mount path: a late success must never write history on a replacement card at the same path.

## One planner, two ways to run it

1. Build the entire plan **without writes**. Keep paths relative to `DCIM`. Group assets by case-insensitive directory + filename stem. RAW/JPEG siblings share a sequence number but are filtered individually. Matching `.XMP`, `.WAV`, `.THM`, `.LRV`, `.AAE` companions follow any selected primary and take the earliest matching primary's capture time/day. Orphans are not brought into selective copies.
2. Sort the **whole card inventory before filtering**, by capture time ascending, breaking ties by relative path. Number each distinct asset on first encounter, starting at 1. Both naming modes use `DEST/YYYY-MM-DD/<DCIM-relative subdirectories>/`. `original` keeps the filename as-is; `timestamp` uses `YYMMDDTHHMMSS_NNNN.EXT` (uppercase extension). Four digits is a **minimum**: `9999`, `10000`, never wrap or re-pad earlier names. Promise stability across selections of the **unchanged** card, not uniqueness across cards.
3. Reject a destination on or inside the source card, traversal, escaping symlinks, duplicate planned destinations, and unresolved existing-file conflicts. Classify each target: new copy, same-size skip (`size`, default), or byte-identical skip (`full`). A nonregular target or different size is a conflict in either mode. Don't invent another filename to work around a conflict. `--dry-run` uses this same planner: show source → proposed names (cap the listing at 200, report the remainder) and accurate totals. No destination directories, partials, media writes, or card history. It is an **ingest** preview, not a guarantee of no host config/log writes; `e` is still a real eject if requested.
4. For a real copy, verify the destination base (or nearest existing ancestor) is still the directory inspected at planning. Use rooted, directory-relative operations, pin the containing directory through publication/cleanup, and revalidate every planned skip at execution. A string-prefix check is insufficient. Check available space for **new bytes only** when the filesystem exposes it.
5. Stream each new file into an exclusively created sibling `<final>.part`. A pre-existing partial blocks that file: never resume, truncate, age out, or remove it. Check length against the plan, sync, and in `full` mode rewind and compare the open source and partial **byte for byte before publication**. Check read/write/seek/sync/close errors and cancellation between chunks; a blocked OS read may still take time. Publish atomically **without replacement**, even if another process created the final after planning (exclusive rename on macOS/Linux; fail if unavailable). On failure remove only this transaction's own partial; leave earlier completed files intact and report them separately. Show counts, bytes, smoothed MB/s, ETA when meaningful, elapsed time, skips, and errors.

## Two different kinds of state

**On the card:** `CARD/.cardbot` is an ingest receipt, not a backup index. Read legacy JSON `$schema: cardbot-dotfile-v1` (single `last_copied` record) in memory. After a successful **real** ingest only, upsert that mode in `cardbot-dotfile-v2`'s `copies` array, preserving other modes. Store `mode`, RFC3339 `timestamp`, `destination`, `files_copied` and `bytes_copied` (including accepted skips), `verified`, `verification_method`, `cardbot_version`. Use a unique exclusive temp, sync/close, then rename. Never create write-access probes. Treat missing or malformed history as no readable record; malformed JSON may be replaced on a later successful ingest, but never overwrite an unknown schema. A history write failure on a locked card is a warning, not a failed media copy. Show **only the latest valid** record or “No recorded ingest”; “photos from ingest day” describes a past operation, not what is safe to erase today.

**On the host:** use `os.UserConfigDir()/cardbot/config.json`. Merge saved JSON over these defaults:

```json
{
  "$schema": "cardbot-config-v1",
  "destination": {"path": "~/Pictures/cardBot"},
  "naming": {"mode": "original"},
  "advanced": {"verify_mode": "size", "buffer_size_kb": 256, "exif_workers": 4, "log_file": "~/.cardbot/cardbot.log"},
  "output": {"color": true},
  "daemon": {"enabled": false, "start_at_login": false, "terminal_app": "Terminal", "launch_args": [], "debug": false},
  "meta": {"last_seen_version": ""}
}
```

- On first interactive use or `--setup`, ask only for destination (macOS folder picker with line-input fallback) and naming mode, save, then continue. `--reset` removes only the saved config and exits. `--version` prints the build identity and exits without setup. `--verbose` shows effective settings. Keep timestamped output readable without color; rotate the optional private log at 5 MiB to `.old` and surface persistent write failures.
- Precedence: explicit `--dest` > `CARDBOT_DESTINATION` > file > default. Also honor `CARDBOT_NAMING`, `CARDBOT_VERIFY_MODE`, `CARDBOT_LOG_FILE`; environment variables must not activate action flags like `--daemon` or `--setup`. Keep run overrides separate from saved preferences. Clamp buffer to 64–4096 KiB and EXIF workers to 1–16; accept legacy `sha256`/`checksum` config values as `full`. Write config as a private (`0600`) synced temp + atomic rename. Warn on malformed, unreadable, or future config; never autosave defaults or version metadata over it.

## Daemon, distribution, and upgrades

- **Headless watcher:** `cardbot --daemon` launches the foreground app for the detected card; it does not ingest. Never prompt. If saved config is absent or invalid, fail before logging, detecting, or autosaving; reject `--daemon` with `--setup` or `--reset`. Hold a lifetime singleton lock alongside `~/.cardbot/cardbot.pid`, clean up the PID on exit, and fail closed if locking is unavailable. Suppress repeated insertions (5-second cooldown) and duplicate foreground launches; a daemon by itself must not prevent manual interactive use.
- **Login integration:** on macOS support `install-daemon` / `uninstall-daemon`. Keep the existing login identity **`com.illwill.cardbot`** under `~/Library/LaunchAgents/` so upgrades find it. Pass the XML-escaped executable and `--daemon` as separate plist arguments. Support Terminal.app, system default, Ghostty (destination-derived working directory and hidden `--target-path-b64`), generic apps, and custom argument lists with `{{cardbot_binary}}` / `{{mount_path}}`. Pass paths as data; test spaces, quotes, and shell metacharacters. Explain Automation vs Full Disk Access failures. `daemon-status [--json] [--recent-launches N]` distinguishes saved settings, foreground guard, running PID, installed vs loaded agent, and recent launcher log lines. `daemon-debug [status|on|off]` persists changes for the next daemon start.
- **Updates:** check on interactive startup with a 5-second timeout; offline is nonfatal, and checking never installs. Show the embedded changelog once on version change, not on first install. Explicit `self-update` compares SemVer against `wdphoto/cardBot` GitHub Releases. For a newer release, require the matching `cardbot-<os>-<arch>` and `checksums.txt`; bound downloads, validate SHA-256 for that exact filename, preserve executable mode, sync/close a same-directory temp and atomically replace only after verification. Errors leave the old executable intact.
- **Install/uninstall:** supply shell scripts for a latest or pinned release, with checksum verification, recorded install path, `--install-dir`, `--no-sudo`, and `--dry-run`. Preserve config/logs unless `--purge` explicitly requests known default files. Limit default removal to recorded/known, version-checked candidates; explicit `--install-dir` authorizes only its `cardbot` file. No broad process kills or recursive home cleanup. A recorded PID plus executable basename is **not proof of daemon role**; don't claim otherwise.
- **Build identity:** embed `VERSION` so a plain build prints `cardbot 0.10.0-dev` for `--version`; `make build` adds commit/dirty state and UTC build date. Do not derive the version from the nearest tag. Provide a guarded release workflow, not a release: stable `vMAJOR.MINOR.PATCH` must match `VERSION` minus `-dev`, be on `main`, and not roll back below the highest stable tag. Keep historical `v0.9.0` and `v0.0.10` intact; `v0.10.0` is the intended next release. Build CGO-free darwin/linux × arm64/amd64 assets, SHA-256 manifest and provenance attestations. Windows amd64 is a CI compile check only.

## Build order and definition of done

Get the fixture above green first: inventory → deterministic plan/preview → verified copy → receipt. Then wire it to the foreground session, detector, daemon/launcher, updater, and packaging. A useful simplification is one read-only inventory feeding both the media overview and the copy planner, rather than two walkers whose rules can drift. It is still a snapshot, not proof that a file hasn't changed. Keep `main`/`cmd` thin, use concrete Go types, and isolate OS, clock, terminal, and HTTP calls for testing. No catalog database, cloud sync, copyright injection, automatic `.part` recovery, or desktop GUI.

Deliver source, a Makefile, README with setup/preview examples, changelog, MIT license, CI and release definitions, and a short testing guide. Acceptance requires:

- Table-driven and temporary-directory tests for the worked example, all six selections, the `9999` → `10000` boundary, dated companions, unknown files, and significant path spaces. Assert **what did not change** as well as what was copied.
- Fault tests for short writes, read errors, insufficient space, failed verification, cancellation, late destination conflicts, changed skips, directory replacement, and preservation of foreign partials. Simulate removal/reinsertion at the same path, read-only history, broken config, singleton contention, and a failed update that leaves the old executable untouched.
- Use tiny synthetic media, temporary homes, fake mount/process/launcher commands, and local HTTP fixtures. Ordinary tests must not enumerate attached cards, eject, run a login agent, install a binary, or contact GitHub. Keep live native detector tests explicitly opt-in (`CARDBOT_TEST_LIVE_DETECTOR=1`); physical removal, sleep/wake, login permissions, and real transfer performance are separate manual QA, not automated pass claims.
- Run `gofmt`, `go test ./...`, `go build ./...`, `go vet ./...`, `make test` (`go test ./... -count=1 -race`), and `make build`. Check `./cardbot --version`. Pin CI tools and action revisions; give workflows only the permissions they need. CI should also check shell syntax/ShellCheck, staticcheck, govulncheck, the cross-build matrix, and the tagged macOS detector. Supply bounded fuzz tests for path/naming, byte comparison, history, SemVer, and checksum parsing, plus representative analysis/planning/verification benchmarks. Report exactly what passed, what could not be run, and what still needs hardware. Stop before installation or release.
